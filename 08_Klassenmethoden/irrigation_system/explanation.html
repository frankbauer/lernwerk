Erklärung

In dieser Aufgabe wird ein Programm in mehrere kleine Klassenmethoden aufgeteilt. Jede Methode erledigt genau eine Teilaufgabe, und die Methoden rufen sich gegenseitig auf. So wird der Code übersichtlicher und einzelne Teile können wiederverwendet werden.

  • Aufbau eines Methodenkopfes:

    Jede Methode beginnt mit einem Methodenkopf, der festlegt, wie die Methode aufgerufen wird:

    private static int waterAmount(int baseAmount, int season)
    • private bzw. public legt fest, wer die Methode aufrufen darf. private-Methoden können nur innerhalb der Klasse Irrigation verwendet werden, public-Methoden auch von anderen Klassen.
    • static macht die Methode zu einer Klassenmethode. Sie gehört zur Klasse selbst und kann ohne Objekt über den Klassennamen aufgerufen werden, z.B. Irrigation.plantCare(...), genauso wie Sie bereits Sensor.getSeason() aufrufen.
    • int ist der Rückgabetyp, also der Datentyp des Ergebnisses. Liefert eine Methode kein Ergebnis, wird stattdessen void geschrieben.
    • waterAmount ist der Name der Methode.
    • In den runden Klammern stehen die Parameter mit Datentyp und Namen. Innerhalb der Methode verhalten sie sich wie Variablen, die beim Aufruf mit den übergebenen Werten belegt werden.
  • Methode mit Rückgabewert: waterAmount

    Die Methode berechnet die Wassermenge und gibt sie mit return zurück. Mit return wird die Methode sofort beendet. Wird also im Sommer baseAmount * 2 zurückgegeben, werden die restlichen Zeilen nicht mehr ausgeführt. Nur wenn weder Sommer noch Winter ist, wird die letzte Zeile erreicht und die unveränderte Menge zurückgegeben.

    private static int waterAmount(int baseAmount, int season) {
    if (season == Sensor.SUMMER) {
        return baseAmount * 2;
    } else if (season == Sensor.WINTER) {
        return baseAmount / 2;
    }
    return baseAmount;
}

    Da der Rückgabetyp int ist, muss die Methode auf jedem möglichen Weg einen int-Wert zurückgeben. Würde das letzte return fehlen, meldet der Compiler einen Fehler.

  • Methoden ohne Rückgabewert: water und fertilize

    Diese beiden Methoden berechnen nichts, sondern führen nur eine Aktion aus, hier eine Ausgabe auf der Konsole. Deshalb ist ihr Rückgabetyp void und sie benötigen kein return.

    private static void water(String plant, int amount) {
    System.out.println(plant + " wird mit " + amount + " ml Wasser gegossen.");
}

    waterAmount, water und fertilize sind private, weil sie nur Hilfsmethoden für plantCare sind. Von außen soll nur plantCare aufgerufen werden.

  • Methoden kombinieren: plantCare

    Die Methode plantCare nutzt die Hilfsmethoden. Zuerst wird die Bodenfeuchte über die Klassenmethode Sensor.getMoisture ausgelesen. Ist der Boden zu trocken, wird die Wassermenge mit waterAmount berechnet, in der Variablen amount gespeichert und an water übergeben.

    int amount = 0;
if (moisture < 30) {
    amount = waterAmount(baseAmount, season);
    water(plant, amount);
} else {
    System.out.println(plant + " muss nicht gegossen werden.");
}

    Beachten Sie, dass waterAmount und water hier ohne Klassennamen aufgerufen werden. Innerhalb derselben Klasse darf der Klassenname weggelassen werden: water(plant, amount) bedeutet dasselbe wie Irrigation.water(plant, amount). Für Methoden einer anderen Klasse wie Sensor.getMoisture ist der Klassenname dagegen nötig.

    Die Variable amount wird mit 0 initialisiert, damit am Ende auch dann ein sinnvoller Wert zurückgegeben wird, wenn nicht gegossen wurde. Die Variablen moisture und amount sind lokale Variablen: Sie existieren nur während des Aufrufs von plantCare. Bei jedem Aufruf werden sie neu angelegt.

    if (season == Sensor.SPRING || season == Sensor.SUMMER) {
    fertilize(plant);
}
return amount;

    Der Rückgabewert wird in der main-Methode verwendet, um den gesamten Wasserverbrauch aufzusummieren: total = total + Irrigation.plantCare("Kaktus", 50);. Beim Probelauf im Winter wird der Rückgabewert dagegen nicht benötigt. Er darf dann einfach ignoriert werden.

  • Überladen: die zweite Variante von plantCare

    Die Klasse enthält zwei Methoden mit dem Namen plantCare, die sich in ihrer Parameterliste unterscheiden (zwei bzw. drei Parameter). Das nennt man Überladen. Beim Aufruf entscheidet Java anhand der übergebenen Parameter, welche Variante ausgeführt wird. plantCare("Kaktus", 50) ruft die Variante mit zwei Parametern auf, plantCare("Tomate", 400, Sensor.WINTER) die mit drei Parametern.

    public static int plantCare(String plant, int baseAmount) {
    return plantCare(plant, baseAmount, Sensor.getSeason());
}

    Die Variante mit zwei Parametern enthält selbst keine Logik. Sie bestimmt nur die aktuelle Jahreszeit und gibt die Arbeit an die Variante mit drei Parametern weiter. Deren Ergebnis wird direkt zurückgegeben. So steht die eigentliche Versorgungslogik nur an einer Stelle im Code. Soll z.B. der Grenzwert von 30 % geändert werden, muss das nur in einer Methode passieren.
